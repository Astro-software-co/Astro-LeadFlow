    **In `frontend/src/lib/api.ts`:**

    1. Create an exported `tokenStore` object at module level (closure-based, NOT localStorage):
    ```typescript
    export const tokenStore = {
      _accessToken: null as string | null,
      _refreshToken: null as string | null,
      get accessToken() { return this._accessToken; },
      get refreshToken() { return this._refreshToken; },
      set(access: string, refresh: string) {
        this._accessToken = access;
        this._refreshToken = refresh;
      },
      clear() {
        this._accessToken = null;
        this._refreshToken = null;
      },
    };
    ```

    2. Update the **request interceptor** to read from `tokenStore.accessToken` instead of `localStorage.getItem('access_token')`.

    3. Replace the **response interceptor** 401 handler with refresh-then-retry logic:
    - On 401, check if `tokenStore.refreshToken` exists
    - If yes, call `authService.refreshToken(tokenStore.refreshToken)` — import authService lazily to avoid circular deps: `const { authService } = await import('@/services/auth.service');`
    - On successful refresh, call `tokenStore.set(newAccess, newRefresh)`, retry the original request with new token
    - Use a module-level `let isRefreshing = false` flag + `let failedQueue: Array<...> = []` to prevent concurrent refresh attempts
    - On refresh failure (or no refresh token), call `tokenStore.clear()` then `window.location.href = '/app/login'`

    4. Remove ALL `localStorage.getItem('access_token')` and `localStorage.removeItem(...)` calls from this file.

    4. The `register` method path `/auth/register` stays as-is but add a comment: `// Backend expects org onboarding fields — registration is private-only, handled in Plan 02`.

  <name>Task 3: Add organizationId to all React Query cache keys</name>
  <files>frontend/src/hooks/api/useDashboard.ts, frontend/src/hooks/api/useLeads.ts, frontend/src/hooks/api/useVehicles.ts</files>
  <read_first>

    - frontend/src/hooks/api/useLeads.ts (current query keys without orgId)
    - frontend/src/hooks/api/useVehicles.ts (current query keys without orgId)
    - frontend/src/contexts/AuthContext.tsx (to see how to get user.organizationId)
  </read_first>
  <action>
    The React Query cache keys currently do NOT include `organizationId`. This means if user A from org-1 logs out and user B from org-2 logs in (same browser session), cached data from org-1 could be served to org-2 — a multi-tenant security breach.

    While `queryClient.clear()` on logout (Task 2) is the primary defense, adding orgId to keys is defense-in-depth and also ensures correct behavior when switching contexts.

    **In each hook file (`useDashboard.ts`, `useLeads.ts`, `useVehicles.ts`):**

    1. Import `useAuth` from `@/contexts/AuthContext`:
    ```typescript
    import { useAuth } from '@/contexts/AuthContext';
    ```

    2. Inside each hook function, get the user:
    ```typescript
    const { user } = useAuth();
    const orgId = user?.organizationId ?? 'unknown';
    ```

    3. Prepend `orgId` to all `queryKey` arrays:

    **useDashboard.ts:**
    - `['dashboard', 'kpis']` → `[orgId, 'dashboard', 'kpis']`
    - `['dashboard', 'monthly-sales']` → `[orgId, 'dashboard', 'monthly-sales']`
    - `['dashboard', 'category-sales']` → `[orgId, 'dashboard', 'category-sales']`
    - `['dashboard', 'recent-sales']` → `[orgId, 'dashboard', 'recent-sales']`

    **useLeads.ts:**
    - `['leads', filters]` → `[orgId, 'leads', filters]`
    - Invalidation keys in mutations: `{ queryKey: ['leads'] }` → use `queryClient.invalidateQueries({ predicate: (query) => query.queryKey.includes('leads') })` OR simply keep `['leads']` as invalidation uses partial matching (it will match any key containing 'leads')

    **useVehicles.ts:**
    - `['vehicles', filters]` → `[orgId, 'vehicles', filters]`
    - Same invalidation pattern as leads

    4. Note: The `useMocks` variable at module level stays — it controls mock vs real data source. The orgId is about cache isolation, not data source.
  </action>
